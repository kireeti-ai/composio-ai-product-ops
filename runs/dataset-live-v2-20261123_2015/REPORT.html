3 Research Engine

Sheet 3 of 5

In plain words: find the official pages, save them, let a model read only those, then check every quotation.

How the evidence was gathered and turned into claims, with the real volumes behind each stage.

What Composio did here

  • Retrieval ran through the Composio Connect MCP endpoint with a consumer key. Tools called through COMPOSIO_MULTI_EXECUTE_TOOL: TINYFISH_SEARCH_WEB and TINYFISH_FETCH_URLS; discovery through COMPOSIO_SEARCH_TOOLS.
  • Every response was checked for instant_charge == 0; any charge aborts the run. Total cost: none.
  • Not demonstrated: the Composio SDK (the key supplied was an MCP consumer key; the SDK returned 401) and per-app toolkit schemas. No integration claim rests on a toolkit name alone.

Decisions that shaped the results

  • Groq’s 8,000 tokens/min cap forced shorter evidence. That cut an answer once (Ahrefs, finding 1), so the reduction is versioned, tested and shown.
  • Frozen prompt, schema and baseline are never edited; every correction is a new directory with its own hashes.
  • One writer at a time, atomic read-only checkpoints, a hash-chained request log, a circuit breaker that stops after repeated provider failures, and a stop at the first daily-quota error.

4 Verification

What was checked, what was corrected, what has not been checked yet.

Independence
  1. Extraction and verification by the same model family are not independent.
  2. JSON validity, lexical quote matching and model agreement are not accuracy measurements.

Five-app correction: the original output beside the corrected one

How a quotation is judged

  • Rejected: placeholders such as “unknown”, quotations joined with an ellipsis, text that is not contiguous on the cited page, URLs missing from the retrieval ledger, and sentences that exist on the page but were not shown to the model (possible recall from memory).
  • A rejected quotation means the evidence does not support the claim as submitted. It does not mean the claim is false.
  • A generic explanation of MCP is not evidence that a given app has an MCP server.

Human evaluation

0 of 252 planned claim labels completed.

Three sample frames of 12 apps (84 claims each) plus a calibration set are prepared, sealed and blank. Two independent labelers and one adjudicator fix the truth by file hash before any model output is opened. Agreement is reported with Cohen’s kappa; Wilson intervals appear only once labels exist. No accuracy, precision, recall or improvement figure is claimed in this report.
