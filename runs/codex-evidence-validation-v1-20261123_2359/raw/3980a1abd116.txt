        <h1 class="post-title" data-swiftype-name="title" data-swiftype-type="string">
          Overview
        </h1>

        <div class="post-content" data-swiftype-name="body" data-swiftype-type="text">
          <p>The Harvest V2 API is a <a href="https://en.wikipedia.org/wiki/Representational_state_transfer">REST API</a> that allows you to interact with your Harvest account programmatically. You can track time, log expenses, create projects, and more.</p>

<h2 id="api-requests">API requests</h2>

<p>Harvest requires applications to authenticate all requests with <a href="/api-v2/authentication-api/authentication/authentication/">OAuth2 or Personal Access Tokens</a>.  The following HTTP methods are supported:</p>

<ul>
  <li>GET</li>
  <li>POST</li>
  <li>PATCH</li>
  <li>DELETE</li>
</ul>

<p>When issuing a GET request, parameters should be included in the URL query string:</p>

<div class="language-plaintext highlighter-rouge"><div class="highlight"><pre class="highlight"><code>curl https://api.harvestapp.com/v2/tasks?page=2&amp;per_page=10 \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Harvest-Account-Id: $ACCOUNT_ID" \
  -H "User-Agent: MyApp (<a href="/cdn-cgi/l/email-protection" class="__cf_email__" data-cfemail="6910061c1b0708040c290c11080419050c470a0604">[email&#160;protected]</a>)"
</code></pre></div></div>

<p>When issuing a POST or PATCH request, parameters should be included in the request body. Request parameters can either be formatted in JSON or submitted as form data. When submitting request parameters as JSON, you must pass <code class="language-plaintext highlighter-rouge">application/json</code> in the <code class="language-plaintext highlighter-rouge">Content-Type</code> header.</p>

<p>We also require that each request include a <code class="language-plaintext highlighter-rouge">User-Agent</code> header with both:</p>

<ul>
  <li>The name of your application</li>
  <li>A link to your application or email address</li>
</ul>

<p>We use this information to get in touch if you’re doing something wrong (so we can warn you before you’re blocked) or something awesome (so we can congratulate you). Here are examples of acceptable <code class="language-plaintext highlighter-rouge">User-Agent</code> headers:</p>

<ul>
  <li><code class="language-plaintext highlighter-rouge">User-Agent: Trello (http://trello.com/contact)</code></li>
  <li><code class="language-plaintext highlighter-rouge">User-Agent: John's Harvest Integration (<a href="/cdn-cgi/l/email-protection" class="__cf_email__" data-cfemail="2943464147694c51484459454c074a4644">[email&#160;protected]</a>)</code></li>
</ul>

<h3 id="notes-about-user-agents">Notes about user agents</h3>

<ul>
  <li>If you don’t include a <code class="language-plaintext highlighter-rouge">User-Agent</code> header, you’ll get a <code class="language-plaintext highlighter-rouge">400 Bad Request</code> response.</li>
  <li>If you use a non-standard User Agent or deviate from the pattern suggested above, you may encounter connectivity issues with Harvest’s API.</li>
</ul>

<h4 id="json">JSON</h4>

<div class="language-plaintext highlighter-rouge"><div class="highlight"><pre class="highlight"><code>curl -X POST https://api.harvestapp.com/v2/tasks \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Harvest-Account-Id: $ACCOUNT_ID" \
  -H "User-Agent: MyApp (<a href="/cdn-cgi/l/email-protection" class="__cf_email__" data-cfemail="b5ccdac0c7dbd4d8d0f5d0cdd4d8c5d9d09bd6dad8">[email&#160;protected]</a>)" \
  -H "Content-Type: application/json" \
  -d "{\"name\":\"My New Task\"}"
</code></pre></div></div>

<h4 id="form-data">Form data</h4>

<div class="language-plaintext highlighter-rouge"><div class="highlight"><pre class="highlight"><code>curl -X POST https://api.harvestapp.com/v2/tasks \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Harvest-Account-Id: $ACCOUNT_ID" \
  -H "User-Agent: MyApp (<a href="/cdn-cgi/l/email-protection" class="__cf_email__" data-cfemail="8ff6e0fafde1eee2eacfeaf7eee2ffe3eaa1ece0e2">[email&#160;protected]</a>)" \
  -d name="My New Task"
</code></pre></div></div>

<h2 id="api-responses">API responses</h2>

<p>Harvest formats response bodies in JSON and uses HTTP response codes to indicate the success or failure of an API request. The following are the HTTP status codes that you may encounter when using the API along with a brief explanation of when they occur.</p>

<table>
  <thead>
    <tr>
      <th>Code</th>
      <th>Explanation</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>200</td>
      <td>Your request was successful.</td>
    </tr>
    <tr>
      <td>201</td>
      <td>A new object has been created. Its representation will be returned in the response body.</td>
    </tr>
    <tr>
      <td>403</td>
      <td>The object you requested was found but you don’t have authorization to perform your request.</td>
    </tr>
    <tr>
      <td>404</td>
      <td>The object you requested can’t be found.</td>
    </tr>
    <tr>
      <td>422</td>
      <td>There were errors processing your request. Check the response body for additional information.</td>
    </tr>
    <tr>
      <td>429</td>
      <td>Your request has been throttled. Refer to the <a href="#rate-limiting">Rate Limiting</a> section for details.</td>
    </tr>
    <tr>
      <td>500</td>
      <td>There was a server error. Contact <a href="/cdn-cgi/l/email-protection" class="__cf_email__" data-cfemail="8ffcfaffffe0fdfbcfe8eafbe7eefdf9eafcfba1ece0e2">[email&#160;protected]</a> for help.</td>
    </tr>
  </tbody>
</table>

<h2 id="rate-limiting">Rate limiting</h2>

<p>We have an <strong>API throttle</strong> that blocks accounts that exceed our API rate limits. We reserve the right to tune the limitations, but they are always set high enough to allow a well-behaving interactive program to do its job.</p>

<ul>
  <li>The rate limit for general API requests is <strong>100 requests per 15 seconds</strong>.</li>
  <li>The rate limit for <a href="/api-v2/reports-api/">Reports API</a> requests is <strong>100 requests per 15 minutes</strong>.</li>
</ul>

<p>For batch processes and API developers who still need to perfect their code, this throttle may be an inadvertent blocker. Just wait a bit, and try again. Since the throttle is reset with each call, the throttle will lift itself in a few minutes and API calls may resume.</p>

<p><strong>When the rate limit is exceeded Harvest will send an HTTP 429 status code.</strong> The number of seconds until the throttle is lifted is sent via the Retry-After HTTP header, as specified in <a href="http://tools.ietf.org/html/rfc2616#section-14.37">RFC 2616</a>.</p>

<p>Please remember to write your application carefully, caching when possible. In case of abuse you may be blocked, disallowing further API access.</p>

<h2 id="conventions">Conventions</h2>

<p>When you encounter a value surrounded by curly braces, you should replace it with a value appropriate to your context.
For example, if your Harvest project’s ID is <code class="language-plaintext highlighter-rouge">1234</code> and the documentation provides the following URL:</p>

<div class="language-plaintext highlighter-rouge"><div class="highlight"><pre class="highlight"><code>https://api.harvestapp.com/v2/projects/{PROJECT_ID}
</code></pre></div></div>

<p>you would replace the <code class="language-plaintext highlighter-rouge">{PROJECT_ID}</code> with the actual project ID, like so:</p>

<div class="language-plaintext highlighter-rouge"><div class="highlight"><pre class="highlight"><code>https://api.harvestapp.com/v2/projects/1234
</code></pre></div></div>

<p>We also make use of shell variables in our example requests (e.g. <code class="language-plaintext highlighter-rouge">$ACCESS_TOKEN</code>). If your operating system supports shell variables, you can set shell variables like this:</p>

<div class="language-plaintext highlighter-rouge"><div class="highlight"><pre class="highlight"><code>ACCESS_TOKEN="my-access-token"
ACCOUNT_ID="my-account-id"
USER_AGENT="MyApp (<a href="/cdn-cgi/l/email-protection" class="__cf_email__" data-cfemail="bfc6d0cacdd1ded2daffdac7ded2cfd3da91dcd0d2">[email&#160;protected]</a>)"
</code></pre></div></div>

<p>Then, you can reference them by prefixing them with a <code class="language-plaintext highlighter-rouge">$</code>:</p>

<div class="language-plaintext highlighter-rouge"><div class="highlight"><pre class="highlight"><code>curl -X POST https://api.harvestapp.com/v2/company \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Harvest-Account-Id: $ACCOUNT_ID" \
  -H "User-Agent: $USER_AGENT"
</code></pre></div></div>

<p>This should allow you to copy/paste most of the example requests without needing to change anything aside from IDs.</p>

      <td><code class="language-plaintext highlighter-rouge">true</code></td>
      <td>Either <code class="language-plaintext highlighter-rouge">true</code> or <code class="language-plaintext highlighter-rouge">false</code>.</td>
    </tr>
    <tr>
      <td>string</td>
      <td><code class="language-plaintext highlighter-rouge">"foo"</code></td>
      <td>A double-quoted sequence of characters.</td>
    </tr>
    <tr>
      <td>integer</td>
      <td><code class="language-plaintext highlighter-rouge">42</code></td>
      <td>A non-negative integer value.</td>
    </tr>
    <tr>
      <td>decimal</td>
      <td><code class="language-plaintext highlighter-rouge">6.8</code></td>
      <td>A decimal value. The supported precision is field-dependent.</td>
    </tr>
    <tr>
      <td>date</td>
      <td><code class="language-plaintext highlighter-rouge">"2017-12-31"</code></td>
      <td>An ISO 8601 formatted string containing just the date portion.</td>
    </tr>
    <tr>
      <td>datetime</td>
      <td><code class="language-plaintext highlighter-rouge">"2017-12-31T14:59:22Z"</code></td>
      <td>An ISO 8601 formatted string containing a UTC date and time.</td>
    </tr>
    <tr>
      <td>time</td>
      <td><code class="language-plaintext highlighter-rouge">"14:59"</code><br /><code class="language-plaintext highlighter-rouge">"2:59pm"</code></td>
      <td>A string containing a 12-hour or 24-hour time depending on the Time Format configured for your account. You can check this on the <strong>Settings</strong> page in your Harvest account or the <code class="language-plaintext highlighter-rouge">clock</code> attribute the <a href="/api-v2/company-api/company/company/">Company API</a>.</td>
    </tr>
    <tr>
      <td>array</td>
      <td><code class="language-plaintext highlighter-rouge">[ 1, 2, 3 </code>]</td>
      <td>A JSON array.</td>
    </tr>
    <tr>
      <td>object</td>
      <td><code class="language-plaintext highlighter-rouge">{ name: "value" }</code></td>
      <td>A JSON object.</td>
    </tr>
